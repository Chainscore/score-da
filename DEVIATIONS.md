# Deviations from the grant application

This file records where the delivered research differs from the W3F grant application ([`da_comparative_study.md`](https://github.com/w3f/Grants-Program/blob/master/applications/da_comparative_study.md)) and the Milestone 1 methodology, with the reason and the effect on the research questions (RQ1 efficiency, RQ2 latency, RQ3 security, RQ4 validator cost).

| # | Planned | Delivered | Reason | Effect |
|---|---|---|---|---|
| 1 | Short active experiments on testnets as the basis of the comparison | Active submission, retrieval, inclusion and throughput tests on all five networks (Aug–Dec 2025, `protocol/active-tests/`, on-chain evidence in `protocol/active-tests/evidence/`), plus a 90-day record of every mainnet block and its DA data across six protocols (~18.8M blocks), which is the basis of the comparison | Testnet throughput, latency and fees depend on each network's own validator set, load and fee policy, so they cannot be compared across protocols or with mainnet. Mainnet block records measure every protocol the same way. | Comparison rests on production data (RQ1, RQ2 block dynamics, cost). Testnet runs are reported as supporting evidence. |
| 2 | Espresso Cappuccino testnet, observing fast path vs fallback | Espresso mainnet: submission, inclusion latency and stress tests; 90-day block record | Espresso moved to mainnet; an outside party cannot trigger the fallback path | Fast path vs fallback not observed (RQ2) |
| 3 | Celestia and Avail light-client sampling runs | Block data read over RPC for every block; sampling confidence derived from protocol parameters | On an honest live network sampling succeeds on essentially every block, so success rates do not separate protocols without withholding, which outside parties cannot cause on mainnet | Sampling covered analytically (RQ2, RQ3); not measured |
| 4 | Polkadot PoV sizes and per-validator bandwidth from an instrumented validator; Kusama as a stress case | Relay-chain inclusion data for every block; PoV size estimated from parachain-side proof size and block bytes (17 parachains, 47% of inclusions); Kusama not collected | The PoV metric (`polkadot_parachain_candidate_validation_pov_size`) is populated only on active validators, which we did not operate | Throughput is an estimate with stated caveats (RQ1); per-validator bandwidth not measured (RQ1, RQ4) |
| 5 | NEAR blob submission and retrieval after pruning | `submit_data` runs on testnet (2,287 calls); DA cost from the in-window gas schedule; 90-day block record | A blob-store client was written but not run; the marginal cost follows from the gas schedule | Retrieval after garbage collection not measured (RQ2) |
| 6 | Validator computational and financial cost | Not measured; published hardware requirements and validator counts in the security analysis | Needs operating validators on several networks | RQ4 answered qualitatively only; stated as a limitation in the paper |
| 7 | Five protocols | Six: Ethereum (EIP-4844/PeerDAS) added | Reference point for the most widely used DA layer | Wider comparison |
| 8 | Collection window at a fixed time | Window extended to 15 Nov 2025 – 14 Feb 2026 | To capture Ethereum Fusaka/PeerDAS, BPO1 and BPO2 and Celestia's 32 MiB blocks | Upgrades used as natural experiments |
| 9 | Jupyter notebooks | Python scripts run by `collect.sh` (transform, plot, tables) | Scripts run unchanged in Docker | Same reproducibility; `protocol/shared/make_tables.py` regenerates every paper table |
| 10 | Running own nodes; Terraform for cloud instances | Public RPCs, indexers (Celenium, NEAR Lake) and BigQuery; one local Celestia light node for active tests | Full history over 90 days from public sources; no cloud instances used, so no Terraform | Collection reproducible from public endpoints |

Corrections made to the analysis after delivery are listed in `CHANGELOG.md`.
