\subsection{Data Collection Framework}
\label{sec:meth-collection}

We collect per-block data from six DA protocols over a 92-day observation window (November~15, 2025 through February~14, 2026) from mainnet RPC endpoints, indexers and public datasets.
Coverage is complete except for NEAR, which lacks February~11--14 (88 days, 12.3M of 12.6M blocks), and Espresso and Avail, which lack November~15. Celestia has no TIA price for November~15, so that day is excluded from its cost statistics.
All protocol parameters (capacities, fork boundaries, gas schedules, retention defaults) are the values in force at the height of each recorded block.

For each protocol, the collector captures the following:

\paragraph{Polkadot}
We scan relay chain blocks via the Polkadot.js RPC API, extracting three event types per block: \texttt{paraInclusion.CandidateBacked}, \texttt{paraInclusion.CandidateIncluded}, and \texttt{paraInclusion.CandidateTimedOut}.
We also parse the \texttt{paraInherent.enter} extrinsic to extract signed availability bitfield counts and per-core availability fractions.
The relay chain does not expose PoV sizes (only commitments), so throughput is estimated as $\text{included} \times \overline{\text{PoV}} / \text{cadence}$, with $\overline{\text{PoV}}$ the inclusion-weighted parachain-side PoV estimate (Section~\ref{sec:meth-normalization}); $\text{included} \times \text{maxPovBytes}$ is kept as an upper bound.
Cost data is collected separately from the Coretime chain, scanning \texttt{broker.Purchased}, \texttt{broker.Renewed}, and \texttt{broker.SaleInitialized} events, as well as relay chain \texttt{onDemand.OnDemandOrderPlaced} events.

\paragraph{Ethereum}
We collect per-block header fields (\texttt{blob\_gas\_used}, \texttt{excess\_blob\_gas}) from the public BigQuery table \texttt{bigquery-public-data.crypto\_ethereum.blocks} across the full 92-day window, which spans four regimes: Pectra (target~6, max~9), Fusaka (same blob parameters, plus PeerDAS and the EIP-7918 reserve price, from block 23{,}935{,}694 on December~3, 2025), BPO1 (target~10, max~15, from block 23{,}975{,}778 on December~9), and BPO2 (target~14, max~21, from block 24{,}179{,}383 on January~7, 2026). Era boundaries are the first blocks at or after each fork's activation slot.
The blob base fee is computed from the header's \texttt{excess\_blob\_gas} using the EIP-4844 exponential pricing formula with the update fraction of the active era.
ETH/USD prices are sampled hourly from CoinGecko.

\paragraph{Celestia}
Block data is retrieved from the Celenium indexer API, which provides 22 columns per block including \texttt{blobs\_size}, \texttt{blobs\_count}, \texttt{square\_size}, \texttt{fill\_rate}, and \texttt{fee\_utia}.
The window spans app version~5 and version~6 (from 24~November 2025), and a maximum-square increase from 128 to 256 (8 to 32~MiB) on 3~December 2025; we compute capacity with the maximum in force on each day.

\paragraph{Espresso}
We fetch all blocks in the window from the Espresso query-service explorer API.
Each block record contains \texttt{size\_bytes}, \texttt{num\_transactions}, and \texttt{block\_time\_ms}.
HotShot is a responsive consensus protocol, so block times vary.
The base fee is 1~wei/byte in every header we sampled between heights 1K and 10.3M.

\paragraph{NEAR}
Blocks and chunk headers are read from NEAR Lake (S3), with NEAR RPC as a fallback.
Per-block fields include \texttt{num\_shards}, \texttt{total\_encoded\_bytes} (sum of chunk encoded lengths), \texttt{total\_gas\_used}, and \texttt{gas\_price}.

\paragraph{Avail}
The collector uses the Polkadot.js API (Avail is Substrate-based) to extract \texttt{submit\_data\_bytes}, \texttt{submit\_data\_count}, and \texttt{block\_fee\_plancks} (from \texttt{TransactionFeePaid} events) per block.
Runtime version (\texttt{spec\_version}) is tracked to account for parameter changes.

\subsection{Metric Definitions}
\label{sec:meth-metrics}

We apply four groups of metrics to every protocol.

\subsubsection{Throughput (MiB/s)}

We distinguish three throughput measures:

\begin{itemize}
    \item \textbf{Protocol maximum}: the theoretical ceiling given current parameters.
    Protocol-specific formulas:
    \begin{align}
        T_{\max}^{\text{Polkadot}} &= \frac{\text{effective\_cores} \times \text{max\_pov}}{\text{cadence}} \label{eq:tmax-polkadot} \\
        T_{\max}^{\text{Ethereum}} &= \frac{\text{max\_blobs} \times 128\text{ KiB}}{\text{slot\_time}} \label{eq:tmax-ethereum} \\
        T_{\max}^{\text{Celestia}} &= \frac{\text{max\_data\_bytes}}{\text{avg\_block\_time}} \label{eq:tmax-celestia}
    \end{align}
    where effective\_cores $= \min(\text{num\_cores}, \lfloor\text{validators}/5\rfloor)$ and cadence is 6s (async backing) for Polkadot.

    \item \textbf{Observed throughput}: measured from production data as
    \begin{equation}
        T_{\text{obs}} = \frac{\sum \text{payload\_bytes}}{\Delta t \times 2^{20}} \quad \text{(MiB/s)}
    \end{equation}
    aggregated at hourly and daily granularity.

    \item \textbf{Utilization}: $U = T_{\text{obs}} / T_{\max}$, representing the fraction of available DA capacity in use.
\end{itemize}

\subsubsection{Cost (\$/MiB)}

The protocols price DA in different units, which we normalize as follows:

\begin{itemize}
    \item \textbf{Per-byte fee markets} (Celestia, Espresso, Avail): cost is computed from on-chain fees and token prices. For Celestia the daily quantiles use the gas price $\times$ 8~gas/byte and exclude the fixed PayForBlobs gas; VWAP divides all fees by blob bytes. For Avail, cost is the transaction fee of each \texttt{submitData} call divided by its payload, so small submissions dominate the per-MiB figure.
    \begin{equation}
        \text{cost\_per\_MiB} = \text{fee\_per\_byte} \times 2^{20} \times \text{token\_USD}
    \end{equation}

    \item \textbf{Blob gas market} (Ethereum): cost is the blob base fee from EIP-4844 exponential pricing; it excludes the execution and priority gas of the carrying transaction:
    \begin{equation}
        \text{cost\_per\_MiB} = \frac{\text{blobBaseFee}_{\text{gwei}} \times 2^{20}}{10^{9}} \times \text{ETH\_USD}
    \end{equation}

    \item \textbf{Coretime pricing} (Polkadot): DA is bundled with execution capacity. We compute:
    \begin{equation}
        \text{cost\_per\_MiB} = \frac{\text{coretime\_price\_DOT} \times \text{DOT\_USD}}{\text{max\_MiB\_per\_region}}
    \end{equation}
    for bulk coretime, and $\text{fee\_paid} / \text{max\_pov\_MiB}$ for on-demand.
    This is a capacity price: it assumes a full PoV in every block.

    \item \textbf{Function-call gas} (NEAR): NEAR has no blob type or DA fee market; rollups post data as function-call arguments. We price DA as the marginal gas of a cross-account call carrying 1~MiB of input, from the in-window gas schedule (identical at protocol versions 81 and 82): per byte, the not-same-receiver send cost plus execution plus the cost of reading the input (\texttt{env::input}); plus fixed receipt and call costs. That is $\sim$60~Tgas per MiB, multiplied by each block's gas price. State storage (1~NEAR per 100~KB) is avoided because input is pruned. NEAR's chain-wide average fee per byte is reported separately and is not a DA cost.
\end{itemize}

We report spot cost at percentiles (p50, p90, p99) and volume-weighted average price (VWAP) over the 92-day window.

\subsubsection{Annualized Cost}

Where a protocol drops DA data after a fixed window, keeping the data available means reposting it periodically.
We define:
\begin{equation}
    \text{cost\_per\_MiB\_year} = \text{cost\_per\_MiB} \times \frac{365}{\text{retention\_days}}
\end{equation}
We define retention uniformly as the default horizon after which a non-archival node no longer serves the data: Polkadot 25~h (availability store), NEAR $\sim$1.5~d (5-epoch garbage collection), Ethereum $\sim$18~d (blob sidecars), and Celestia 7~d (the light-node sampling window; bridge and full nodes store 30~days by default). Avail retains block bodies by default and Espresso does not prune unless configured, so neither has a default horizon and we report their spot cost only. The resulting figures are illustrative repost costs, not prices offered by the protocols.

\subsubsection{Block Dynamics}

We measure block time distributions (p10, p50, p90), block size distributions, and empty block rates.
For protocols with variable block times (Espresso's responsive HotShot consensus), we report the empirical distribution rather than a fixed value.

\subsection{Normalization and Comparability}
\label{sec:meth-normalization}

Comparing these protocols raises six methodological issues:

\begin{enumerate}
    \item \textbf{Demand-constrained measurements}: window-mean utilization ranges from 0.18\% to 35\%; only Ethereum exceeded 3\%, at $\sim$60\% of its maximum before BPO1. Observed throughput therefore reflects demand, and we report protocol maximum throughput alongside it.

    \item \textbf{Token price volatility}: USD-denominated costs are sensitive to token prices, which fluctuated during our window (daily means: ETH \$1,821--\$3,357; TIA \$0.31--\$0.82). We use contemporaneous hourly prices from CoinGecko rather than fixed spot rates, and report VWAP alongside percentile distributions.

    \item \textbf{Pricing units}: Polkadot sells blockspace (coretime), Ethereum prices blob gas, and Celestia and Espresso charge per byte. We convert all to \$/MiB. For Polkadot two biases act in opposite directions: amortizing over maximum PoV capacity understates the cost per MiB actually used ($\sim$34$\times$ at 2.9\% utilization), while attributing the whole coretime price to DA overstates the DA share. The figure is a capacity price, not an observed DA cost.

    \item \textbf{Estimated throughput for Polkadot}: the relay chain does not expose PoV sizes (only commitments). We estimate the mean PoV from parachain-side proof size and extrinsic bytes for 17 parachains covering 47\% of inclusions, weighted by inclusion share, and multiply by included candidates. The proxy is uncompressed, so it overstates the real PoV; Section~\ref{sec:disc-limitations} gives the range.

    \item \textbf{Protocol upgrades within window}: Ethereum underwent three upgrades (Fusaka, BPO1, BPO2) and Celestia transitioned eras during our observation period. We segment analysis by protocol era where applicable and compare the periods before and after each transition (Section~\ref{sec:results-upgrades}).

    \item \textbf{Throughput measurement conventions}: Two definitional choices affect comparability with other sources (e.g., L2Beat).
    First, for Ethereum we report protocol maximum throughput using the \emph{absolute maximum} blob count per block (21 under BPO2), whereas some trackers use the EIP-4844 \emph{target} blob count (14 under BPO2), below which fees trend toward zero. The target is the fee-market equilibrium and the maximum is the hard protocol ceiling.
    Second, for Celestia we measure \emph{user data throughput} (the original data square, ODS), not the full 2D Reed--Solomon encoded square. The extended square is $4\times$ larger (a $k{\times}k$ ODS becomes $2k{\times}2k$ after encoding), so sources that report total encoded bandwidth will show approximately $4\times$ our figures. We report user data throughput because it reflects the amount of application-level data that can be posted per unit time.
\end{enumerate}

\subsection{Reproducibility}
\label{sec:meth-reproducibility}

Collection and analysis code, the raw per-block data and the figures are released under Apache~2.0 (code) and CC~BY~4.0 (data) at \repolink. All tables and figures are regenerated from the raw data by the released scripts.
